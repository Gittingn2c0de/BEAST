# BEAST generation backends — v1.1

## Decision

The mandatory Hugging Face Inference API path has been removed. BEAST's image-generation route now targets a replaceable, self-managed worker contract. The default is **unconfigured**, so BEAST cannot silently send prompts to a third party or incur inference charges.

## What works now

- Creative planning, prompt synthesis, SVG generation (when the separately configured Mercury text API is available), visual-language settings, local asset storage, and conventional FFmpeg film assembly remain separate from raster inference.
- CANVAS can store a remote worker URL and optional bearer token in local `workspace/settings.json`.
- Raster generation calls `POST {workerUrl}/api/generate/image` and only stores an asset after receiving actual base64 image bytes.
- Accepted response: `{"imageBase64":"<base64>","mimeType":"image/png","model":"optional model label"}`. Accepted MIME types are PNG, JPEG and WebP. Request includes `prompt`, `negativePrompt`, `width`, `height`, `format`, and `project`.
- The application rejects unsupported schemes, embedded URL credentials, unsupported image types, empty images and image payloads above 35 MB. A configured URL is not treated as verified until a real request succeeds.
- If no worker is configured, the image endpoint returns HTTP 503 with a clear explanation. It does not create a fake image or report success.

## What is not implemented / not claimed

- This repo does not include a GPU, a hosted GPU endpoint, a ComfyUI workflow, or an actual worker process.
- No live remote worker has been tested by this change.
- AI video generation is not connected. The existing FFmpeg path assembles still frames; it is not generative animation.
- Mercury 2.5 remains a separate text/creative-intelligence provider and still requires its own Inception Labs API key for those features. Removing Hugging Face inference does not make text inference free or local.

## Zero-budget constraint

A self-managed remote GPU server with zero budget is not something this code can provision by itself. Until you have access to a machine you control that can run the worker, raster image generation remains unavailable. You can still develop the project, compile prompts, create vector/graphic SVGs where the Mercury key is configured, organize assets, and assemble existing raster images into review videos.

## Future worker implementation

Implement the worker separately behind this API contract. It can use ComfyUI, Diffusers, or another inference runtime internally without changing BEAST's UI or creative pipeline. Worker must authenticate requests, enforce a queue and concurrency limits, validate input sizes, return generated bytes, and expose health/queue status. Do not expose a GPU worker directly to the public internet without authentication and TLS.
